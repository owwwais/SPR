### الدفعة 2 — صحة البيانات والأداء
**الإحصائيات كانت تكذب:** الشركة لديها **8,000** طلب والصفحة تعرض **5,000**. كل رقم — المجاميع، المتوسطات، القمع — محسوب على بيانات مبتورة **بلا أي تحذير**. `org_stats()` يجمّع في القاعدة الآن.

| الخطة | Seq Scan + Hash Join | **Index Scan لعشرين صفاً** |

### الدفعة 3 — فرض الحصة (`D16`)
الحصص **من صفحة الأسعار نفسها** لا مخترعة: تجربة 25 · أساسية 150 · نمو 750. الفحص **داخل `analyze-application` قبل نداء النموذج**. **مُثبَت:** 3 نداءات تمرّ على حصة 3، الرابع يُرفض، والإفراج يُعيد وحدة.
فشل **قبل** النموذج ⇒ استرداد. فشل **بعده** ⇒ لا استرداد (المال أُنفق). ونفاد الحصة يترك الطلب **مقروءاً يدوياً** — `D4` سليم.

### الدفعة 4 — تقرير الشفافية (`D24`)
تصدير HTML لكل طلب: الدرجة، التفصيل، التبرير، **إصدار الموجّه والنموذج**، و**من غيّر الحالة ومتى**. الإشعار الاستشاري **داخل** الوثيقة لا حولها فقط. مصرَّح مرتين: بوابة المسار + فحص العضوية في الدالة.

### الدفعة 5 — الفرز المُعمّى + السعودة
**المُعمّى:** مرحلة تجهيل منفصلة، والتقييم لا يرى إلا النصّ المجهّل — **الملف الأصلي لا يصل المرحلة الثانية إطلاقاً**. فشل التجهيل ⇒ **فشل التشغيل**، لا رجوع للأصل. **اختياري ومطفأ افتراضياً** (يضاعف الكلفة).
> **`prompts.ts`: 46 إضافة، صفر حذف** — الموجّه التقييمي سليم حرفياً كما يفرض §10.8.

**السعودة:** ⚠️ **النظام لا يستنتج الجنسية إطلاقاً.** الموظف البشري يسجّلها، عند **مرحلة المقابلة أو العرض فقط**، وثلاث حالات (نعم/لا/**لم يُسجَّل**). **خارج درجة الملاءمة تماماً.**

### 🔴 المرحلة 1 — قبل أي نشر (30 دقيقة)

**1. راجع الكود ثم ادمج الـPR.** الفرع `claude/audit-august-2026-pajah5`.

**2. طبّق الهجرات على بيئة تجريبية أولاً — لا الإنتاج.**
**من GitHub:** Actions ← *Deploy Supabase* ← Run workflow ← ضع علامة على
«Also apply pending database migrations» ← Run.
**أو من اللوحة:** SQL Editor ← الصق كل ملف هجرة بالترتيب `0012` → `0017`.
راجع `0013` تحديداً: يضيف عموداً ويعيد تعبئته.

**3. اضبط إعدادات مهمة التنظيف** — **بدونها لن تعمل مهمة الحذف اليومية** (التزام `D8`):
```sql
alter database postgres set app.housekeeping_url =
  'https://<ref>.supabase.co/functions/v1/housekeeping';
alter database postgres set app.housekeeping_key = '<anon key>';
```
ثم أعد تشغيل `0012`. **`0012` سيصرخ `WARNING` إن لم تفعل** — وهذا مقصود.

**4. انشر الدوال الطرفية:** لا شيء لتفعله — **تُنشَر تلقائياً** عند دمج هذا
الـPR في `main`. تابع التقدّم في تبويب **Actions**.

**5. اضبط أسرار الدوال — ومن أين تأتي كل واحدة:**

| السرّ | من أين | ملاحظة |
|---|---|---|
| `SITE_URL` | **أنت تكتبه** — نطاق موقعك، مثل `https://hakeem.sa` | بلا `/` في آخره. تُبنى منه روابط التحقق في البريد؛ خطؤه يعني رابطاً معطّلاً في كل رسالة |
| `THROTTLE_SALT` | **تولّده أنت**: `openssl rand -hex 32` | ملح تجزئة عناوين IP والبُرد. لا يُشتق من مكان — أي سلسلة عشوائية طويلة تكفي. **غيّره ⇒ تُصفَّر عدادات الحدّ** |
| `TURNSTILE_SECRET_KEY` | **من Cloudflare** — لوحة التحكم ← Turnstile ← Add site. مجاني | تأخذ مفتاحين: **Site Key** (عام، يذهب لـVercel باسم `NEXT_PUBLIC_TURNSTILE_SITE_KEY`) و**Secret Key** (سرّي، يذهب لـSupabase) |
| `GEMINI_API_KEY` | Google AI Studio | موجود مسبقاً — تأكّد فقط أنه من **الطبقة المدفوعة** (البند 12) |
| `RESEND_API_KEY` | لوحة Resend | موجود مسبقاً |

**من اللوحة (بلا CLI):** Project Settings ← Edge Functions ← Secrets ← Add new secret.
و`NEXT_PUBLIC_TURNSTILE_SITE_KEY` يُضاف في **Vercel** لا في Supabase (فهو عام ويحتاجه المتصفح).

> **`THROTTLE_SALT` بلا طرفية:** أي سلسلة عشوائية طويلة تكفي — مثلاً من
> `https://www.random.org/strings/` (32 خانة، حروف وأرقام). لا يُشتق من أي خدمة.

> ⚠️ **Turnstile مطلوب فعلياً الآن:** منصة المواهب **تفشل مغلقة** بدونه — أي أن الرفع سيُرفض. (نموذج التقديم للوظائف يفشل مفتوحاً عمداً، حتى لا يُحرَم متقدّم حقيقي من فرصة بسبب عطل عندنا.)

**6. أنشئ دلو `talent-cvs`** — تنشئه `0017`، تأكّد فقط أنه **خاص** (`public = false`).

**6.5. 🔴 اكشف مخطط `talent` في الواجهة البرمجية — خطوة واحدة يدوية لا غنى عنها.**
هذا اكتُشف أثناء التشخيص الفعلي: مخطط `talent` أُنشئ **غير مكشوف عمداً** لعزل البيانات، لكن الدوال الطرفية تستدعيه عبر `supabase-js` الذي يمرّ دائماً عبر PostgREST — حتى بمفتاح الخدمة. وPostgREST يرفض أي مخطط غير موجود في قائمته **قبل** أن يصل الطلب لقاعدة البيانات أو RLS، بخطأ `PGRST106`. **بدون هذه الخطوة، كل رفعة سترفض دائماً.**

هذا **إعداد على مستوى المشروع نفسه**، لا تلمسه الهجرات ولا النشر العادي. أضفتُ مهمة مخصصة له:
`Actions ← Deploy Supabase ← Run workflow ← ✅ "Expose talent schema" ← Run`
(مرة واحدة فقط، بعد نشر `0017`. آمنة: RLS يبقى الحماية الفعلية — نفس وضع كل جداول `public` — لا مخطط `talent` نفسه.)

> ⚠️ **لا تستخدم مربع «Also apply pending database migrations»** — هجرات

>
> **ولماذا يهمّ هذا فوراً:** الكود ينتشر تلقائياً عند الدمج والهجرات لا. ما

### ما تفعله أنت — بالترتيب

1. **طبّق الهجرات:** Actions ← Deploy Supabase ← Run workflow ← Database: `apply` ← Run.
   يطبّق `0025` و`0026` (و`0023`/`0024` إن لم تكن طبّقتهما). قبل ذلك تعمل
   الصفحات لكن تقول «غير مفعّلة بعد» وتعرض «اليوم» الأرقام الأساسية فقط.
2. **اجعل نفسك مدير منصة** — في Supabase ← SQL Editor (ضع بريدك):
   ```sql
   insert into platform_admins (user_id, note)
   select id, 'owner' from auth.users where email = 'بريدك@example.com';
   ```
   ثم افتح `/platform`. يظهر رابط «لوحة المنصة» أسفل قائمتك الجانبية.
3. **بيانات التحويل البنكي** — في Vercel ← Settings ← Environment Variables
   (Production) ثم Redeploy: `BILLING_ACCOUNT_NAME` و`BILLING_BANK_NAME`
   و`BILLING_IBAN`. بدونها تقول الصفحة للعميل إن البيانات ستصله بالبريد.
4. **لتجربة الباقات:** أنشئ حساب شركة ثانياً، ثم من `/platform` افتح المؤسسة
   ← «تطبيق باقة دون دفع». الحدود تتغيّر فوراً وتظهر في صفحة «الباقة
   والاستهلاك» لتلك المؤسسة.

### قرارات لك وحدك (لم أتخذها)

- **الفوترة الضريبية:** الفاتورة التي تصدر عند التأكيد سجلّ داخلي مرقّم
  تسلسلياً وفيه الضريبة محسوبة، **وليست فاتورة ضريبية إلكترونية متوافقة مع
  «فاتورة» (ZATCA)**. قبل تحصيل أي مبلغ: التسجيل في ضريبة القيمة المضافة
  وربط مزوّد فوترة إلكترونية معتمد. الأعمدة اللازمة موجودة في الجدول.
- **انتهاء التجربة:** صفحة الأسعار تقول «14 يوماً»، لكن لا شيء في النظام
  يُنهي التجربة: باقة «تجربة» دائمة بحدودها الصغيرة. حدّد ما يحدث بعد المدة
  (إيقاف النشر؟ تنبيه فقط؟) لأبنيه، أو احذف «14 يوماً» من الصفحة.
- **المقابلات لكل باقة:** حصة المقابلات صفر في كل الباقات (أي مطفأة) حتى
  تحدد أرقامها — من `/platform` لمؤسسة بعينها، أو في جدول `plans` للجميع.
- **الدفع بالبطاقة (Moyasar)** ومدة الاشتراك السنوي وأسعاره.
- **صحة الأسعار المنشورة:** `/pricing` نصوص ثابتة في `lib/i18n/ar.ts`،
  والحدود المفروضة في جدول `plans` — وهما متطابقان اليوم. أي تعديل سعر أو
  حدّ يكون في الاثنين معاً، وإلا وعدت الصفحة بما لا يُفرض.
