## P1 — حسابات الباحثين عن عمل

### ما يراه الباحث
| | |
|---|---|
| **التسجيل** | تبويبان: «أبحث عن عمل» و«أمثّل شركة». التبويب يحدّد الصفحة التالية فقط، ولا يدخل في أي صلاحية. وروابط تأكيد البريد صارت تمر بـ `/auth/callback` فتدخل المستخدم مباشرة بدل إعادته لصفحة الدخول |
| **الانضمام بالسيرة أولاً** | ① رفع PDF أو DOCX ② بيانات التواصل **أثناء** التحليل، فلا انتظار فارغ ③ مراجعة ما استُخرج: الحقائق قابلة للتعديل، والمهارات **للإخفاء فقط** ④ موافقتان منفصلتان واختياريتان: صفحة مهنية عامة، والظهور للشركات |
| **`/me`** | الرئيسية · الوظائف بزر «تقدّم بملفك» · طلباتي (الحالة وتواريخها، **بلا أي درجة أو تقييم**) · ملفي (حتى 3 نسخ من السيرة) · الإعدادات (الموافقات، وحذف بيانات الباحث فوراً) |
| **التقديم بالملف** | موافقة صريحة **لكل شركة ولكل وظيفة**، وتحصل الشركة على **نسختها الخاصة** من السيرة في مجلدها. التقديم كضيف باقٍ كما هو |
| **الملف القديم بلا حساب** | إن طابق بريده المؤكَّد بريد الحساب يُعرض ربطه **بموافقة صاحبه**، ولا يُربط آلياً. والصفحة العامة القديمة تبقى تعمل |
| **حساب واحد بقبعتين** | الباحث يستطيع إنشاء مساحة شركة، وموظف الشركة يستطيع إنشاء ملف باحث، وفي كل جهة رابط للأخرى |

**ما تراه الشركة:** شارة «قدّم عبر حسابه» فقط، بلا أي بيانات فوق ما شاركه المتقدم.

### الحماية والخصوصية
- **القبعة من الصفوف**: عضوية في `memberships` تعني شركة، وصف في `talent.profiles` مرتبط بالمستخدم يعني باحثاً. لا شيء يُقرأ من `user_metadata` (D26).
- **مخطط `talent` بلا أي صلاحية جدول للعملاء**: كل قراءة وكتابة تمر بدوال `public.talent_*` تحدّد المستخدم من `auth.uid()` وتعيد أعمدة محددة، فلا مسار سيرة ولا بصمة تصل للمتصفح.
- **ثغرة أغلقتها أثناء العمل:** رمز الصفحة العامة `/t/…` كان يكفي لتعديل الملف أو حذفه. صار لا يدير إلا الملفات القديمة غير المرتبطة بحساب.
- **الحذف**: الملف ونسخ السيرة وملفاتها تُحذف **فوراً**. الطلبات المقدّمة تبقى لدى الشركات بنسختها وبلا رابط بالحساب. والحساب نفسه يُحذف إن لم يكن له دور في شركة، **ويُبقى** إن كان صاحبه قد اتخذ يوماً قرار حالة في شركة، لأن ذلك السجل هو دليل أن القرار بشري (D24).
- **الهجرة `0022`**: أزلت صلاحيات كتابة متبقية لـ `anon` على أربعة جداول، و`TRUNCATE` من الدورين على كل الجداول. لم تكن قابلة للاستغلال بسبب RLS، لكنها تخالف §10.11، وصار اختبار يتأكد من خلوّ الكتالوج منها.

## I1 — بنك أسئلة المقابلة

| | |
|---|---|
| **بنك أساسي لكل وظيفة** | يُولَّد مرة واحدة، ثم تراجعه الشركة **سؤالاً سؤالاً**: اعتماد، أو تعديل **يُحفظ بجوار الأصل الذي ولّده النموذج**، أو حذف، أو استرجاع، أو «ولّد بديلاً». ثم يُقفل ببصمة SHA-256 ولا يتغير بعدها، وأي تعديل لاحق نسخة جديدة. المراجعة إلزامية: لا قفل وفيه سؤال لم يُبتّ فيه |
| **قبل أن يرى الموظف أي سؤال** | يُرفض ما يمس الفئات المحمية (عربي وإنجليزي، مع اختبارات للكلمات البريئة مثل «مدينة» و«الديون» و«عمر الجلسة» و«توزيع الحمل»)، والأسئلة العامة («حدّثنا عن نفسك»)، والمكرر، وأي مخرج لا يطابق المخطط (D5). والفلتر نفسه يطبَّق على تعديلات الموظف |
| **لكل متقدم** | أسئلة استيضاح من سيرته المستخلصة: **بلا اسم**، ونص السيرة يُعامل كبيانات غير موثوقة. مراجعتها اختيارية. والقفل يسحب **خطة المقابلة**: التمهيدي أولاً، ثم المزيج من البنك المقفل بترتيب مختلف لكل متقدم، ولها بصمة |
| **الكلفة** | كل استدعاء للنموذج يمر بوحدة واحدة. سقف استدعاءات ورموز لكل بنك ولكل مقابلة **يُحجز قبل الاستدعاء**. كل استدعاء يُسجَّل **بلا أي محتوى**، والسجل يُحذف بعد 90 يوماً |
| **رصيد المقابلات (D33)** | عمود `monthly_interview_quota` لكل شركة، **افتراضيه 0**: المقابلات مطفأة حتى تحدد الأرقام (البند 7 أدناه). يُفرض **داخل الوكيل** في نفس معاملة إنشاء المقابلة، ويُعاد إن فشل التخطيط. وتوليد البنوك يحتاج رصيداً، وله حد يومي لكل شركة |
| **ما لم يأتِ بعد** | الإرسال للمتقدم وغرفة المقابلة (I2). ومهام البرمجة (I4) والصوت (I5) يرفضها الوكيل صراحةً حتى ذلك الحين، وتظهر في الواجهة «قريباً» |

## P3 — صفحة الهبوط بـ GSAP وLenis وReact Bits

| القسم | الأداة |
|---|---|
| **البطل** | خلفية **DotGrid** تتفاعل مع المؤشر باللون الأخضر المزرق · عنوان بخط 100px يصعد **كلمةً كلمة** · زر رئيسي بـ **Magnet** · ثلاث شاشات حقيقية من المنتج تتبدّل في **CardSwap** (درجة الملاءمة، ومهمة المقابلة، والوظائف المرشّحة) |
| **العبارة الافتتاحية** | **ScrollReveal**: تتضح كلمةً كلمة مع التمرير |
| **«هكذا يفكّر حكيم»** | مشهد **مثبّت بـ GSAP ScrollTrigger**: السيرة ← الحقائق ← أشرطة المعيار مع عدّاد يصل إلى 82 ← «القرار لك». وعلى الجوال أو مع تقليل الحركة تظهر الخطوات الأربع متتالية دون تثبيت |
| **المنتج** | شبكة bento غير متماثلة من **SpotlightCard** يتبع فيها ضوءٌ المؤشر، وتدخل بـ **AnimatedContent** |
| **المقابلة الافتراضية** | غرفة مقابلة مصغّرة، وخطوات التقييم السبع تُعلَّم بالتتابع، **مع شارة «قريباً»** لأن الميزة لم تُطلق بعد |
| **الإنصاف** | الخصائص التي نتجاهلها **تُشطب واحدة واحدة** بـ GSAP، والخط يُرسم من بداية القراءة |
| **الباحثون** | بطاقات تتراكم بـ CSS sticky، وهو يعمل مع Lenis لأنه يُبقي التمرير الأصلي |
| **الخاتمة** | **SplitText** للعنوان، و**Magnet** للزر |
| **التمرير** | **Lenis** على هذه الصفحة وحدها، متزامن مع ScrollTrigger في حلقة واحدة، **ولا يُحمَّل لمن طلب تقليل الحركة** |

**مكونات React Bits السبعة** في `srp/components/react-bits/`، و**قرأتها كاملة قبل إدخالها**: لا اتصال بالشبكة ولا `eval`. واستبعدت **MagicBento** (1,417 سطراً) و**CardSwap** بنسخته الكاملة لأنهما يجلبان `@hugeicons` غير المعتمدة، وأزلت من CardSwap صوره التجريبية. والرخصة في `LICENSE.md` بجوارها.

**تعديلات العربية على المكونات:** SplitText يقسّم **بالكلمات** افتراضياً لا بالحروف (A1) · ScrollReveal بلا ميلان (كان يدور حول الحافة اليسرى) · CardSwap بلا نص إنجليزي لقارئ الشاشة. وأصلحت ستّ ملاحظات من قواعد React Hooks في الكود المنسوخ بدل تعطيل القواعد.

| | النتيجة | الحد في الخطة |
|---|---|---|

## الدخول بـ Google
زر **«المتابعة باستخدام Google»** في صفحتي الدخول والتسجيل، بتدفق PKCE من Supabase. ونجح ما يمكن اختباره دون مشروع حقيقي:
- التوجيه إلى Google يحمل `provider=google` وتحدي PKCE (S256)، ويُحفظ ملف التحقق في الكوكيز.
- الإلغاء عند Google يعيد المستخدم إلى الدخول مع رسالة عربية واضحة.
- رابط بكود مزوّر ووجهة خارجية (`//evil.example`) **يبقى داخل الموقع**.

والاسم من حساب Google يُملأ مسبقاً في نموذج إنشاء الشركة، للعرض فقط.

### 🔴 ما تفعله أنت لتفعيل Google
1. **Google Cloud Console** ← APIs & Services ← OAuth consent screen: نوع External، والاسم «حكيم»، وبريد الدعم ونطاقك.
2. **Credentials** ← Create OAuth client ID ← Web application:
   - Authorized JavaScript origins: `https://<نطاقك>`
   - Authorized redirect URIs: `https://<ref>.supabase.co/auth/v1/callback`
3. **Supabase** ← Authentication ← Sign In / Providers ← **Google**: فعّله، والصق Client ID وClient Secret.
4. **Supabase** ← Authentication ← URL Configuration: Site URL = `https://<نطاقك>`، وأضف `https://<نطاقك>/auth/callback` إلى Redirect URLs.
5. تأكّد أن `NEXT_PUBLIC_SITE_URL` مضبوط في Vercel.

قبل هذه الخطوات يعمل الزر، لكنه يعيد المستخدم إلى صفحة الدخول برسالة «تعذّر تسجيل الدخول عبر Google».
