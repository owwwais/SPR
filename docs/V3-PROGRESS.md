## I0 — عقد الوكيل وهيكله

### في `interview-agent/` (الخادم المستقل)
| البند | التفصيل |
|---|---|
| **واجهة المنصة** | `POST/GET/DELETE /v1/platform/interviews` والإلغاء ورمز الجلسة. **كل طلب موقَّع HMAC**، مع نافذة زمنية خمس دقائق، ورفض الطلب المعاد (nonce)، و`Idempotency-Key` للإنشاء |
| **جلسات المتقدم** | رمز Ed25519 صالح 15 دقيقة. **جهاز واحد حيّ**: الرمز الجديد يُبطل القديم. والمؤقّت يحسبه الخادم ويشمل الوقت الإضافي المسموح |
| **دورة الحياة** | آلة الحالات كما في الوثيقة §1.3، وكل انتقال يُسجَّل في `audit_log` |
| **الأحداث** | صندوق صادر (outbox) يُكتب في نفس معاملة التغيير، ويُرسَل موقَّعاً مع إعادة محاولة بتأخير متزايد. **حدث لا يضيع** حتى لو توقف الخادم بين الخطوتين |
| **المحو** | `DELETE` يمحو المقابلة وكل ما تحتها في استعلام واحد |
| **النشر** | `Dockerfile`، والهجرات خطوة منفصلة، و`.env.example` يشرح كل سرّ |

### في حكيم
| البند | التفصيل |
|---|---|
| **هجرة `0019`** | `interview_assignments` و`interview_reports` و`interview_webhook_events`. **`org_id` يُشتق بـ trigger** ولا يُقبل من الكاتب، والقراءة لأعضاء الشركة فقط، والكتابة للخادم وحده |
| **`apply_interview_event()`** | يسجّل الحدث ويطبّق حالته **في معاملة واحدة**. المكرَّر يُتجاهل، والأقدم لا يكتب فوق الأحدث |
| **`interview-gateway`** | إنشاء وإلغاء بصلاحية **شركة الطلب نفسها**. **يحذف الاسم** قبل الإرسال، ولا يرسل الملف أبداً |
| **`interview-webhook`** | يتحقق من التوقيع قبل قراءة أي شيء، و`verify_jwt = false` لأن التوقيع هو المصادقة |
| **الاحتفاظ** | `housekeeping` يمحو المقابلة من الوكيل **قبل** حذف الطلب. إن فشل المحو يبقى الطلب للدورة التالية، فلا تبقى نسخة يتيمة على الخادم الآخر |
| **العقد المشترك** | `contract` و`hmac` **نسختان متطابقتان حرفاً بحرف** في المشروعين، واختبار يفشل عند أي اختلاف |

### التحقق
```
interview-agent   npm test            34/34 (منها قاعدة بيانات حقيقية، و0 متخطّى)
                  typecheck · build   نظيف
srp               tenant_isolation    53/53
                  onboarding          23/23
                  interview_isolation 31/31   ← جديد
                  rls_check           صفر إخفاقات
                  tsc · eslint · build نظيف
Edge Functions    deno check          نظيف (gateway · webhook · housekeeping)
```
**وتجربتان طرفيتان حقيقيتان عبر الحدود** (لم تدخلا CI لأن Deno غير موجود فيه):
1. **الوكيل ← دالة الويب هوك (Deno):** الحدث الصحيح يصل إلى `apply_interview_event` بمعاملاته الصحيحة. السرّ الخاطئ ← 401. والتوقيع لدالة أخرى ← 401. والحدث المعطوب ← 400 دون أي كتابة.
2. **دالة البوابة (Deno) ← الوكيل (Node + Postgres):** الإنشاء نجح، و**الاسم لم يصل الوكيل** رغم وجوده في السيرة المستخلصة. والإعداد الخاطئ رُفض قبل الإرسال. والإلغاء وصل وولّد حدثه.

## 🔴 ما تفعله أنت

### الآن — لا شيء يتعطّل إن تأخّرت
البوابة تعيد `503 interviews_not_configured` ما دام الوكيل غير مُعَدّ، ولا واجهة تستدعيها بعد. **الإنتاج الحالي لا يتأثر.**

| # | الخطوة | التفصيل |
|---|---|---|
| 1 | **راجع الفرع وادمجه** | — |
| 2 | **طبّق الهجرة `0019`** | Actions ← Deploy Supabase ← ✅ migrations، أو الصقها في SQL Editor |
| 3 | **استضف الوكيل في منطقة سعودية** | مثلاً GCP الدمام `me-central2`: حاوية من `interview-agent/Dockerfile` + Postgres صغيرة. شغّل `node dist/db/migrate-cli.js` مرة لكل نشر |
| 4 | **ولّد الأسرار** | `openssl rand -hex 32` لكل من: مفتاح المنصة ← الوكيل، وسرّ الويب هوك. و`npm run keygen` لمفتاح الجلسات |
| 5 | **أسرار الوكيل** | `DATABASE_URL` · `PLATFORM_HMAC_KEYS=k1:<الأول>` · `WEBHOOK_URL=https://<ref>.supabase.co/functions/v1/interview-webhook` · `WEBHOOK_SECRET=<الثاني>` · `SESSION_SIGNING_JWK` · `ALLOWED_ORIGINS=https://<نطاقك>` |
