## 2. البوابة المزدوجة — الطلب ①

### 2.1 نموذج الهوية
```
auth.users (هوية واحدة: بريد + كلمة مرور)
   ├─ public.profiles         ← الاسم فقط (هوية، كما في D14)
   ├─ public.memberships      ← «قبعة الشركة»: (org, role) — لم يتغير شيء
   └─ talent.profiles.user_id ← «قبعة الباحث»: الملف والسيرة والتفضيلات
```
- **التوجيه:** `/admin/*` يحتاج عضوية (`requireMembership` كما هو)، و`/me/*` يحتاج ملف باحث (**`requireSeeker`** جديدة في `lib/auth.ts`). من له القبعتان يرى مبدّلاً في رأس الصفحة.
- **التبويب المختار عند التسجيل** يُحفظ **تلميحاً للتوجيه فقط** (إلى أي مسار انضمام نرسله)، **ولا يُستخدم للصلاحية أبداً**. الصلاحية تأتي حصراً من الصفوف.
- **العبور بين المنتجين** يمر **بمعرّف المستخدم** (`auth.users.id`) وبدوال `public.talent_*`، لا بمفتاح أجنبي من `public` إلى `talent`. هكذا تبقى قاعدة «لا `join` مباشر بين المخططين» قائمة.

### 2.2 التسجيل — تبويبان
```
┌───────────────────────────────────────┐
│   [ أبحث عن عمل ]   [ أمثّل شركة ]     │  ← تبويبان، والافتراضي من الرابط (?as=seeker)
│                                       │
│   البريد الإلكتروني  [               ] │
│   كلمة المرور        [               ] │
│   [ إنشاء الحساب ]                     │
│   لديك حساب؟ تسجيل الدخول              │
└───────────────────────────────────────┘
```
- **الشركة:** المسار الحالي كما هو (تأكيد البريد ← `/onboarding` ← اسم الشركة والرابط).
- **الباحث:** تأكيد البريد ← `/onboarding/seeker`.
- **تأكيد البريد إلزامي قبل أي تحليل.** هذا هو ضابط الكلفة الأهم في `TALENT-PLATFORM-DESIGN.md` §7، ويبقى كما هو: لا يُستهلك استدعاء مدفوع لبريد لم يثبت وجوده.

### 2.3 انضمام الباحث — السيرة أولاً، كما طلبت
```
① السيرة الذاتية      ارفع PDF أو DOCX (≤ 5MB، فحص البصمة الثنائية)
                       ← يبدأ التحليل فوراً في الخلفية (≈ 20–40 ثانية)
② بيانات التواصل       تُملأ أثناء التحليل: الجوال (مطلوب للتقديم) · المدينة
                       · نوع العمل المفضّل · الاستعداد للانتقال
                       ← كل ما يمكن استخراجه من السيرة لا نسأل عنه
③ المراجعة             ما استخرجناه: الحقائق قابلة للتعديل، والتحليل للحذف فقط
                       (القاعدة القائمة في TALENT-PLATFORM-DESIGN §2)
④ الموافقات (منفصلة، وكلها اختيارية)
     ☐ صفحة مهنية عامة برابط فريد
     ☐ أن تراني الشركات في «مرشحون مقترحون» وتدعوني للتقديم
   ← لوحة الباحث
```
- **الانتظار مُخبّأ:** الخطوة ② تُملأ أثناء التحليل، فلا يرى المستخدم دوّاراً فارغاً.
- **الثقة المنخفضة:** إن كانت ثقة الاستخلاص منخفضة، نطلب نسخة أوضح من السيرة قبل الإكمال. وهذه قاعدة قائمة.
- **حدود قائمة تبقى:** 3 رفعات في اليوم لكل حساب، وبصمة SHA-256 تجعل رفع الملف نفسه مرة ثانية بلا استدعاء جديد.

### 2.4 بوابة الباحث — `/me`
| الصفحة | المحتوى |
|---|---|
| `/me` | **الرئيسية:** وظائف مرشّحة لك، وملخص حالات طلباتك، و**مهام المقابلات** بعدّاد تنازلي |
| `/me/jobs` | تصفّح السوق كله، مع شارة «مناسبة لك» وسببها |
| `/me/applications` | طلباتك بحالاتها وتواريخها. **تحلّ محل التتبّع بالرمز** للمسجّلين، ويبقى الرمز للضيوف |
| `/me/interviews` | المقابلات الافتراضية (الوثيقة المرافقة §1.2) |
| `/me/profile` | الملف ونسخ السيرة (التحديث يعيد التحليل، ضمن الحدود)، وتفعيل الصفحة العامة |
| `/me/settings` | الموافقات، وحذف الحساب **حذفاً فورياً كاملاً لبيانات الباحث** (مع شرح أن الطلبات المقدّمة لدى الشركات تخضع لاحتفاظ تلك الشركات) |

### 2.5 التقديم دون إعادة رفع السيرة
```
صفحة الوظيفة ← [ تقدّم بملفك ]
  ┌──────────────────────────────────────────────┐
  │ السيرة: cv-2026-10.pdf (آخر نسخة)  [تغيير]    │
  │ أسئلة الوظيفة (إن وُجدت)                      │
  │ رسالة مختصرة (اختيارية)                        │
  │ ☐ أوافق على مشاركة سيرتي وبيانات تواصلي مع     │
  │   «شركة س» لهذه الوظيفة                        │
  │ [ إرسال الطلب ]                               │
  └──────────────────────────────────────────────┘
```
**المسار الخلفي** (امتداد لـ `submit-application`، فالكتابة تبقى من الخادم وحده كما يشترط D15):
1. Server Action يمرّر **JWT المستخدم** إلى `submit-application` بنمط `profile`.
2. الدالة تتحقق من ملف الباحث، **وتشتق `org_id` من الوظيفة** كما تفعل اليوم.
3. تنسخ السيرة بمفتاح الخدمة من `talent-cvs` إلى `cvs/{org_id}/{application_id}.{ext}`.
4. تُدرج الطلب ومعه `applicant_user_id = auth.uid()`، والاسم والبريد والجوال من الملف.
5. باقي الخط كما هو: التحليل غير متزامن (D4)، ومنع التكرار بـ`(job_id, email)`، والرمز المرجعي، وبريد التأكيد.

**التقديم كضيف يبقى** (D21). الحساب راحة للباحث، **لا بوابة إجبارية** تُفقدنا متقدمين.

### 2.6 ترشيح الوظائف
**النسخة الأولى — قواعد قابلة للشرح** في دالة SQL واحدة `recommended_jobs_for_me()`:

| العامل | الوزن | المصدر |
|---|---|---|
| تقاطع المهارات المعيارية | 50 | `jobs.skill_ids` ∩ مهارات الباحث |
| سنوات الخبرة مقابل الحد الأدنى | 20 | `min_years_experience` |
| المدينة (أو العمل عن بُعد) | 15 | `location` / التفضيلات |
| نوع العمل المفضّل | 15 | `type` / التفضيلات |

- المجموع **للترتيب فقط**. يرى الباحث **الأسباب** («تطابق 4 من 6 مهارات: React، TypeScript…»)، **لا رقماً**. الرقم يخلق توقعاً («أنا مناسب 85%») ثم يصطدم بالرفض، والدرجة الحقيقية نسبية لوظيفة ويحسبها تحليل الشركة (`TALENT-PLATFORM-DESIGN` §3).
- **شرط مسبق صريح:** التصنيف المعياري اليوم **36 مهارة عامة فقط**، فـ«React» لا تقابل شيئاً. النسخة الأولى تحتاج **توسيعه إلى ≈ 300 مهارة بتسلسل هرمي** (React ⊂ الواجهات الأمامية ⊂ تطوير البرمجيات)، وتحتاج حقل `jobs.skill_ids` يُملأ عند حفظ الوظيفة من جدول المرادفات نفسه.
- **النسخة الثانية — دلالية:** `pgvector` وتضمين لكل وظيفة عند النشر ولكل نسخة سيرة. الترتيب هجين (قواعد + تشابه دلالي). يحتاج إضافة نموذج تضمين إلى D2، ويأتي بعد أن تثبت الأولى قيمتها.

### 2.8 RLS والاختبارات
- مخطط `talent` **أصبح مكشوفاً** (`813c547`)، فـ **RLS هو خط الدفاع الوحيد** فيه. السياسة الجديدة: `user_id = (select auth.uid())` للقراءة والتعديل المحدود، **والكتابة الحساسة عبر دوال** (النشر، الموافقات، الحذف).
- **مجموعة اختبارات جديدة `supabase/tests/seeker_isolation.sql`**، وتُضاف إلى `npm run test:db` وإلى CI:
  - الباحث (أ) لا يقرأ ملف الباحث (ب)، ولا نسخ سيرته، ولا طلباته.
  - الباحث لا يقرأ `applications` ولا `ai_evaluations` مباشرة.
  - موظف الشركة لا يرى ملف باحث **إلا** عبر «مرشحون مقترحون»، **وإلا** بموافقة الاكتشاف، **وإلا** بالأعمدة المجهّلة.
  - `my_applications()` لا تُعيد صفاً لغير صاحبه.
  - `anon` لا يكتب شيئاً في أي مكان (§10.11).

### 2.9 ملفات المواهب الحالية (بلا حساب)
- **الصفحات العامة `/t/{token}` تبقى تعمل** كما هي.
- عند أول دخول لباحث **ببريد مؤكَّد يطابق** بريد ملف قديم مؤكَّد: «وجدنا ملفاً مرتبطاً ببريدك، هل تربطه بحسابك؟». **الربط بموافقته**، لا آلياً.
- `/talent` تتحول إلى صفحة تسويق للباحثين، ويفتح زرّها التسجيل على تبويب «أبحث عن عمل».

## 4. إعادة التصميم — الطلب ④

### 4.1 ما هي هذه الأدوات بالضبط؟
| الأداة | نوعها | أين تعمل |
|---|---|---|
| **GSAP** (3.15) | مكتبة حركة: خطوط زمنية، و`ScrollTrigger`، و`SplitText`. **كل الإضافات مجانية منذ 3.13** | صفحة الهبوط، في متصفح الزائر |
| **Lenis** (1.3) | تمرير ناعم **فوق التمرير الأصلي**، فيبقى `sticky` والروابط الداخلية وإمكانية الوصول سليمة | صفحة الهبوط فقط |
| **React Bits** | **مكونات تُنسخ كمصدر** في المشروع عبر سجل shadcn (`@react-bits/…-TS-TW`). ليست حزمة واحدة | صفحة الهبوط |
| **taste-skill** | **مهارة لوكيل البرمجة**: تعليمات يقرؤها الوكيل وأنا أبني التصميم، **ولا تصل للمستخدم أبداً**. أنسبها لنا `redesign-existing-projects` و`minimalist-ui` | أداة تطوير في `.claude/skills/` |
| **awesome-design-md** | **مجموعة وثائق `DESIGN.md`** تحلّل أنظمة تصميم مواقع معروفة (Linear وNotion وStripe وClaude…). وثائق، لا كود | مرجع لكتابة `DESIGN.md` الخاص بحكيم |

**الرخص:** GSAP برخصة GreenSock القياسية المجانية · Lenis تحت MIT · React Bits تحت MIT مع Commons Clause، أي **مسموح استخدامها في منتجنا التجاري، والممنوع إعادة بيع المكونات نفسها** · taste-skill تحت MIT.

### 4.2 مخاطر العربية والاتجاه من اليمين لليسار — تُكتب في `DESIGN.md` قواعدَ ملزمة
| الخطر | لماذا | القاعدة |
|---|---|---|
| **تقسيم النص العربي إلى حروف** (`SplitText type: "chars"`) | كل حرف في عنصر مستقل **يكسر اتصال الحروف العربية**، فتظهر الكلمة حروفاً مقطّعة | **التقسيم بالكلمات أو الأسطر فقط** للنص العربي، دائماً |
| **تقليص المسافة بين الحروف** | وثائق awesome-design-md كلها تضع `letterSpacing` سالباً للعناوين، وهذا مصمَّم لخطوط لاتينية | **لا تتبّع سالب على العربية.** يُطبَّق على اللاتينية والأرقام فقط |
| **اتجاه الحركة** | «ادخل من اليسار» في LTR تعني «من البداية»، وفي RTL البداية يمين | دالة مساعدة تقلب الإشارة بحسب `dir`، **ولا قيم `x` حرفية** |
| **الحركة لمن لا يريدها** | دوار الحركة وحساسيتها | `gsap.matchMedia()` مع `prefers-reduced-motion`، وإيقاف Lenis كلياً عند التقليل |
| **Lenis في لوحة التحكم** | الجداول والحاويات الداخلية تحتاج تمريراً أصلياً | **Lenis على مجموعة مسارات التسويق فقط** |
| **الخطوط اللاتينية المقترحة** | taste-skill يقترح Geist وSatoshi وغيرهما، وكلها بلا عربية | الخط العربي هو الأساس، وقواعدنا تتقدّم على اقتراحات المهارة |

### 4.3 صفحة الهبوط — GSAP + Lenis + React Bits
**القصة بالتمرير:**
| # | القسم | الحركة |
|---|---|---|
| 1 | **البطل:** عنوان يكشف كلماته كلمةً كلمة، وخلفية محيطة هادئة، وزرّان واضحان: «أنا شركة» و«أبحث عن عمل» | `SplitText` بالكلمات، وخلفية من React Bits **تُحمَّل كسولاً** ومعها صورة ثابتة بديلة |
| 2 | **بابان:** لوحة مقسومة بين الشركات والباحثين | تأثير مغناطيسي عند التحويم |
| 3 | **«من سيرة إلى قرار» — اللحظة المميِّزة:** مشهد مثبّت، كلما مرّر الزائر تحوّلت السيرة إلى حقول مستخلصة، ثم أشرطة المعيار تمتلئ، ثم سطور التبرير، ثم «القرار لك» | `ScrollTrigger` مثبّت بخط زمني واحد، و`CountUp` للأرقام. **هذه اللحظة تحكي D24 بلا شرح** |
| 4 | **المقابلة الافتراضية:** غرفة مقابلة مصغّرة، وخطوات التقييم السبع تُعلَّم واحدة تلو الأخرى | خط زمني بالتمرير |
| 5 | **الإنصاف:** ما نتجاهله، بخط يشطب كل بند | حركة شطب |
| 6 | **للباحثين:** الملف، والترشيح، والتقديم بضغطة | بطاقات |
| 7 | **الأسعار والدعوة الأخيرة** | — |

- **مكونات React Bits المرشّحة** (تُتحقَّق أسماؤها من السجل عند البناء): `SplitText` (بالكلمات فقط)، و`BlurText`، و`ScrollReveal`، و`CountUp`، و`SpotlightCard`، و`Magnet`، وخلفية واحدة خفيفة. **كل مكوّن يجلب اعتمادية جديدة** (motion أو ogl أو three) **يُعرض عليك قبل إضافته**، وأفضّل ما يعتمد على GSAP وحده.
- **لا أرقام مخترعة.** لا «+500 شركة» ولا «+10,000 مرشح» قبل وجودها. نعرض حقائق المنتج الصحيحة (مثل: «118 فحصاً آلياً لعزل البيانات بين الشركات»)، أو لا نعرض أرقاماً.
- الصفحة تبقى **ثابتة (static)**، والحركة في جزر عميل صغيرة.

### 4.4 النظام الداخلي — taste-skill + awesome-design-md
**المنهج:**
1. نختار **وثيقة مرجعية** من awesome-design-md **للبنية والصرامة**، لا لنسخ هوية علامة أخرى. نسخ هوية Linear أو Stripe كما هي غير مقبول.
2. نكتب **`srp/DESIGN.md` الخاص بحكيم** بنفس الصيغة: الألوان، والخطوط، والأحجام، والزوايا، والمسافات، والظلال، والحركة، والمكونات، **مع قواعد العربية في §4.2**.
3. نثبّت `redesign-existing-projects` من taste-skill، فيتبع الوكيل منهجيتها: فحص كل صفحة قائمة، ثم تشخيص، ثم إصلاح دون كسر الوظائف. **سأقرأ كل ملف في المهارة قبل إدخاله المستودع**، لأن المهارات قد تحتوي سكربتات تُشغَّل.
4. الرموز تدخل `globals.css` (`@theme`)، فتتغير كل المكونات القائمة (shadcn + `@base-ui/react`) **دون إعادة كتابتها**.

**ثلاثة اتجاهات — اختر واحداً:**
| | **أ. «حبر وورق»** ⭐ | **ب. «دقّة ليلية»** | **ج. «مؤسسي ناعم»** |
|---|---|---|---|
| **المرجع** | Claude + Notion | Linear | Stripe |
| **الإحساس** | دافئ، تحريري، هادئ | كثيف، تقني، فاخر بصمت | أنيق، مؤسسي، تدرّجات مدروسة |
| **الخلفية** | أبيض مائل للدفء | أسود عميق | أبيض نقي |
| **اللون المميِّز** | واحد عميق (أخضر مزرق أو زعفراني) | واحد (بنفسجي أو فيروزي) | تدرّج بنفسجي |
| **الوضع الليلي** | لاحقاً | هو الأساس | لاحقاً |
| **يناسب** | **الاسم «حكيم»: الحكيم يشير ولا يحكم**. ثقة وهدوء | لوحة التحكم بالذات | البيع للمؤسسات الكبيرة |
| **المخاطرة** | قد يبدو «لطيفاً» أكثر من اللازم للوحة كثيفة | مظلم على جمهور غير تقني | الأوزان الخفيفة (300) **تضعف قراءة العربية** |

**توصيتي:** **(أ) للواجهات العامة وبوابة الباحث**، مع **قواعد الكثافة من (ب)** في لوحة الشركات: جداول مضغوطة، وحدود رفيعة، واختصارات لوحة المفاتيح لاحقاً. كل ذلك تحت **رموز واحدة**.

**الخطوط:** IBM Plex Sans Arabic **يبقى** لنصوص الواجهة (ممتاز للعربية). خط عرض للعناوين الكبيرة في الهبوط فقط (مثل Readex Pro أو Alexandria أو Noto Kufi Arabic)، يُختار بتجربة بصرية، ويُستضاف ذاتياً عبر `next/font`. والأرقام بعرض ثابت (`tabular-nums`) في الجداول.

### 4.5 ميزانية الأداء وإمكانية الوصول
| المقياس | الحد |
|---|---|
| **LCP** على جوال متوسط | ≤ 2.5 ثانية |
| **CLS** · **INP** | < 0.1 · < 200ms |
| JavaScript إضافي للهبوط | ≤ 100KB مضغوطاً (GSAP ونواته وإضافتان + Lenis في الحدود) |
| خلفيات WebGL | كسولة، ومعطّلة عند تقليل الحركة وعلى الأجهزة الضعيفة، ولها بديل ثابت |
| لوحة التحكم | بلا Lenis وبلا GSAP ثقيل. حركات دقيقة بـ CSS و`tw-animate-css` (موجودة) |
| التباين | AA على الأقل في كل رموز الألوان، في الوضعين |
